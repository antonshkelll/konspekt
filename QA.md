## Demo 2 · 14.11.2026

19 автотестов проходят; `pip check` и `git diff --check` без ошибок. Новые проверки: демо не вызывает LLM и не открывает аудиоустройства; личная повестка восстанавливается и не заменяется демонстрационной при выходе; отменённый запрос не дописывает ответ; переключение истории сохраняет текущий ответ; компактная панель показывает выбранный ответ. Автотесты покрывают HTTP SSE, ошибки API и обрыв потока, маршрутизацию Ollama/DeepSeek, `thinking=disabled`, финальный WAV-фрагмент и сведение стерео в моно, отказ квоты STT, ограничения вложений, изоляцию встреч/ответов, автоматику и передачу ответа из фонового потока в Qt с контекстом вложения.

Дополнительно проверяются обработка пустого баланса DeepSeek, отключение проблемного системного прокси Deepgram и увеличенный лимит R1/таймаут локальной модели. На этом ПК WebSocket Deepgram через автоматически выбранный прокси зависал на TLS; прямое соединение прошло. В настройках добавлен отдельный выбор прокси.

Модели Ollama находятся на `D:\OllamaModels`. `deepseek-r1:1.5b` (1,1 ГБ) загружена, digest подтверждён Ollama. В тестах с лимитами 100 и 300 токенов R1 генерировала размышления без готового ответа даже при запросе отключить thinking. Для выбора R1 лимит повышен до 2048, однако быстрый полный ответ R1 не подтверждён. Рабочий профиль использует ранее установленную `qwen3.5:4b`.

Измерения Qwen на CPU: первый холодный ответ в одном тесте — 107,57 с; отдельный тест показал 40,39 с загрузки модели, 1,93 с обработки 40 входных токенов и 2,69 с генерации ответа. В полном тесте с контекстом первый текст пришёл через 25,88 с после LLM-запроса, весь ответ — за 30,83 с; распознавание WAV отдельно заняло 7,14 с. Это замеры конкретных запросов, а не гарантия задержки. Перезагрузка модели, контекст и нагрузка на ПК существенно влияют на результат.

Последний smoke-тест адаптера Ollama с контекстом: первый текст 19,69 с, полный ответ 29,69 с; бюджет и срок названы верно. Синтетический поток Deepgram завершён успешно.

При обычном запуске EXE обнаружен конфликт ICU: QtCore импортирует `ucnv_open`, а PyInstaller подхватывал из PATH библиотеку Poppler с экспортами вида `u_getVersion_78`. Исходники использовали штатную ICU Windows и работали. В отслеживаемом `Konspekt.spec` исключена посторонняя `icuuc.dll`, а `build.bat` переведён на этот spec для воспроизводимого исправления.

Проверки, которые пока не выполнены:

- Прямой облачный DeepSeek проверен и вернул HTTP 402 (недостаточный баланс); пользователь выбрал локальную LLM. Его генерация не зачтена как пройденная. Deepgram и локальная Qwen прошли описанные живые тесты.
- Демонстрация экрана в конкретном клиенте созвона: успешный Windows API не доказывает исключение окна во всех способах захвата.
- Полный сценарий реальных кликов/трея: инструмент Windows вернул `FrameArrived timed out`, `coordinate input geometry is unavailable`, затем `user input was detected in this window`. В окне пользователь включил защиту захвата; дерево элементов доступно. Полный сценарий кликов не зачтён как пройденный.
- Серверный Ollama: подготовлен Compose и SSH-инструкция; на сервере не развёрнут и не проверен.

В первичном локальном тесте аудиоустройств аудио не сохранялось и не отправлялось по сети. В живых тестах Deepgram использовалась синтетическая русская речь, в тестах LLM — вымышленные бюджет и сроки. Ключи не включены в репозиторий и отчёт.
